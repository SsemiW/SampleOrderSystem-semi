# PRD

## 1. 배경 및 목적

반도체 시료의 요청·주문·생산·출고 과정을 하나의 콘솔 애플리케이션으로 통합 관리
고객, 주문 담당자, 생산 담당자 세 역할이 협력하여 시료 주문이 접수된 시점부터 출고 완료까지의 전체 흐름을 추적하고, 재고·생산 현황을 실시간으로 파악할 수 있도록 함

---

## 2. 사용자 및 역할

| 역할 | 주요 책임 |
|------|-----------|
| 고객 | 원하는 시료와 수량을 주문 요청 |
| 주문 담당자 | 고객 요청을 주문서로 생성, 주문 승인·거절 처리 |
| 생산 담당자 | 시료 등록, 생산라인 운영, 생산 완료 후 출고 대기 전환 |

---

## 3. 용어 정의

| 용어 | 정의 |
|------|------|
| 시료 (Sample) | 시스템에서 관리하는 생산 단위. 고유 ID·이름·평균 생산시간·수율을 속성으로 가짐 |
| 수율 | 정상 시료 수 ÷ 총 생산 시료 수. 생산 과정의 불량률을 반영 |
| 실생산량 | 부족분을 채우기 위해 실제로 생산해야 할 수량. 수율과 오차(0.9)를 고려해 산출 |
| 총생산시간 | 평균 생산시간 × 실생산량. 생산 완료까지 소요되는 예상 시간 |
| 생산 큐 | 재고 부족으로 생산이 필요한 주문들이 대기하는 대기열. FIFO 방식으로 처리 |
| 생산라인 | 시료를 하나씩 순차적으로 생산하는 설비 흐름 단위 |

---

## 4. 핵심 도메인

### 4.1 시료 (Sample)
시스템의 기본 단위. 고유 ID·이름·평균 생산시간·수율을 가지며, 등록된 시료만 주문이 가능하다.  
수율 = 정상 시료 / 총 생산 시료

### 4.2 주문 상태 흐름

```
RESERVED → CONFIRMED   (재고 충분 시 즉시 승인)
RESERVED → PRODUCING   (재고 부족 시 생산라인 자동 등록)
RESERVED → REJECTED    (거절)
PRODUCING → CONFIRMED  (생산 완료)
CONFIRMED → RELEASE    (출고 처리)
```

| 상태 | 의미 |
|------|------|
| RESERVED | 주문 접수 |
| REJECTED | 주문 거절 (모니터링 제외) |
| PRODUCING | 승인 완료, 재고 부족으로 생산 중 |
| CONFIRMED | 승인 완료, 출고 대기 |
| RELEASE | 출고 완료 |

### 4.3 생산량 산출
- 실생산량 = ceil(부족분 / (수율 × 0.9))
- 총생산시간 = 평균생산시간 × 실생산량
- 생산 큐 스케줄링 전략: FIFO (선입선출)

### 4.4 재고 상태 표기

| 표기 | 조건 |
|------|------|
| 여유 | 주문 대비 재고 충분 |
| 부족 | 주문 대비 재고 수량 부족 |
| 고갈 | 수량 0 |

---

## 5. 주요 기능 요약

| 기능 | 설명 |
|------|------|
| 시료 관리 | 시료 등록, 전체 목록 조회(재고 포함), 이름 검색 |
| 시료 주문 | 고객명·시료 ID·수량 입력으로 RESERVED 주문 생성 |
| 주문 승인/거절 | RESERVED 목록 확인 후 승인(재고 판단 자동 분기) 또는 거절 |
| 모니터링 | 상태별 주문 수 집계, 시료별 재고 여유/부족/고갈 표기 |
| 생산라인 | 생산 현황(진행 중) 및 대기 큐(FIFO) 표시, 생산 완료 시 CONFIRMED 전환 |
| 출고 처리 | CONFIRMED 주문 선택 → RELEASE 전환 |

---

## 6. 제약 사항

- 생산라인은 시료 하나씩 순차 생산 (병렬 생산 없음)
- 주문은 등록된 시료에 한해서만 가능
- REJECTED 주문은 모니터링 및 출고 대상에서 제외

---

## 7. 핵심 시나리오

### 시나리오 A — 재고 충분 주문 처리
1. 생산 담당자가 시료를 시스템에 등록하고 재고를 확보해 둔다.
2. 고객이 해당 시료와 수량을 요청 → 주문 담당자가 주문을 생성 (`RESERVED`).
3. 주문 담당자가 주문 목록에서 해당 주문을 승인한다.
4. 시스템이 재고를 확인하여 충분하다고 판단 → 주문 상태가 `CONFIRMED`으로 즉시 전환.
5. 주문 담당자가 출고 처리를 실행 → 주문 상태가 `RELEASE`로 전환되어 완료.

### 시나리오 B — 재고 부족 주문 처리
1. 고객이 시료를 요청 → 주문 담당자가 주문 생성 (`RESERVED`).
2. 주문 담당자가 승인을 시도하나 재고가 부족한 상태.
3. 시스템이 실생산량·총생산시간을 산출하고 해당 주문을 생산 큐(FIFO)에 자동 등록 → 주문 상태 `PRODUCING`.
4. 생산라인에서 순서대로 생산이 진행되며, 생산 현황에서 진행 상태를 확인할 수 있다.
5. 생산 완료 시 주문 상태가 `CONFIRMED`으로 전환 → 이후 출고 처리로 `RELEASE` 완료.

### 시나리오 C — 주문 거절
1. 주문 담당자가 `RESERVED` 목록에서 특정 주문을 거절 처리한다.
2. 주문 상태가 `REJECTED`로 전환되며 모니터링 및 출고 대상에서 제외된다.
